# Demonstration guide

This walkthrough describes how to demonstrate the application locally. Repository inspection makes read-only GitHub API requests when you submit a public repository; no request is made just by starting the services. Use the default mock provider for a no-cost local workflow, or obtain explicit approval before enabling a hosted LLM provider.

## 1. Start the services

Create and activate the environment, install the project, and copy the safe configuration template as described in the [README setup](../README.md#local-setup-windows-powershell). Keep real credentials in the ignored local `.env` file only.

In PowerShell terminal one, from the project root:

```powershell
python -m uvicorn repo_agent.api.main:app --app-dir src --reload
```

In PowerShell terminal two, from the project root:

```powershell
python -m streamlit run src/repo_agent/ui/streamlit_app.py
```

Open the Streamlit URL printed in terminal two. The API is available at `http://127.0.0.1:8000`; `/docs` shows the FastAPI schema. The UI should report which backend provider is active. With defaults, the model provider is a local deterministic mock; GitHub inspection still requires network access.

## 2. Inspect a public repository

1. Enter a public GitHub URL, for example `https://github.com/pallets/flask`.
2. Select **Inspect repository**.
3. Review the repository name, default-branch commit SHA, selected-file count, and bounded list of eligible text files.
4. Open a file expander to view its path, blob SHA, commit SHA, and pinned file link.

Inspection is a read-only snapshot. The selected files are bounded by settings in `.env.example`; a truncated GitHub tree or size limits can make the selection incomplete.

## 3. Ask a RAG question

Ask a specific source-grounded question, such as:

> How does the project classify GitHub rate-limit errors? Cite the relevant implementation.

The answer may be insufficient if relevant files were not indexed, retrieved, or included within the context limit. Expand **RAG retrieval trace** to compare indexed files, retrieved chunks, and chunks sent to the LLM. Open the source references to inspect line ranges and the pinned commit. The server constructs those links from verified chunks; a citation’s provenance alone does not demonstrate that every answer claim follows from it.

## 4. Run the read-only agent

Agent mode is disabled by default. To opt in, set `AGENT_ENABLED=true` in the backend environment and restart FastAPI. For live agent inference, the backend provider must also be enabled and the selected model endpoint must support the native Chat Completions tool-calling protocol. The mock provider is not a substitute for protocol support in a live model.

Ask a task that benefits from multiple evidence lookups, for example:

> Find the function that handles GitHub rate-limit responses, inspect its behavior, and cite the source.

The interface shows the final answer, commit, number of model steps and tool calls, plus an expandable trace with tool names, sanitized arguments, statuses, and returned file references. It does not show hidden reasoning or private prompts. Agent citations must resolve to evidence returned during that run.

## 5. Reading the evidence

- A **retrieved** chunk was returned by search; it may not fit in the final model prompt.
- A **prompt-included** chunk was actually sent to the RAG model.
- An **agent tool reference** identifies evidence returned by an executed tool call.
- Citation paths, line ranges, and commit-pinned URLs are generated by the server after validating stable evidence IDs.
- An explicit insufficient-evidence result is preferable to a guessed answer. Follow the cited link and compare the claim with the exact source range.
- The evaluation report’s mechanical relevance score checks expected file/range overlap; it does not score semantic correctness.

## 6. Suggested portfolio screenshots

Capture these from a real local run after removing any private repository names, tokens, personal account information, and sensitive browser/terminal details:

1. **Repository snapshot:** repository overview with commit SHA and selected-file list.
2. **RAG evidence:** a question and answer beside the expanded trace showing retrieved versus prompt-included chunks and a source citation.
3. **Agent workflow:** a final answer with an expanded safe tool trace showing tool names, statuses, source references, and call counts.
4. **API surface (optional):** FastAPI `/docs` showing the inspect, analyze, ask, and agent routes.

No screenshots are bundled with this guide. Add only images captured from the actual running application, and review each image before publication to ensure it contains no credentials, private paths, or unsupported performance claims.

## 7. Reproducible offline checks

Run tests from `tests\unit` so a root `.env` is not loaded by settings-based tests:

```powershell
Push-Location tests\unit
python -m pytest -q -c ..\..\pyproject.toml .
Pop-Location
```

Run the offline evaluation from the root:

```powershell
python -m repo_agent.evaluation.cli
```

It uses the benchmark’s pinned local Git commit and mock provider; it makes no GitHub or OpenAI requests. See the [audited results](../evaluation/reports/offline_mock-a2da9850fdd1.md) and [evaluation architecture](architecture.md#evaluation-architecture).
